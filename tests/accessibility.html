Accessibility Testing for Pune AI Collective Website

This page provides manual accessibility testing guidelines and automated test runners for WCAG 2.1 AA compliance.

Target: Pune AI Collective Website

1. Keyboard Navigation Testing

Test keyboard accessibility using only the Tab, Shift+Tab, Enter, Space, and Arrow keys.

Keyboard Navigation Test Area

Use Tab to navigate through these elements:

Test Link 1 Test Link 2
  • All interactive elements are reachable with Tab key
  • Tab order is logical (left to right, top to bottom)
  • Focus indicators are visible on all focusable elements
  • Navigation links work with Enter key
  • Mobile menu opens/closes with Enter and Escape keys
  • Skip links work properly
  • No keyboard traps (can exit any element)

2. Screen Reader Testing

Test with screen reader software (NVDA, JAWS, VoiceOver, or Orca).

  • Page title is announced correctly
  • Headings structure makes sense (H1 → H2 → H3)
  • Landmark regions are identified (nav, main, footer)
  • Link purposes are clear from text or aria-label
  • Form labels are associated with inputs
  • Images have appropriate alt text or aria-hidden
  • Dynamic content changes are announced
  • Social media links have descriptive labels

3. Color and Contrast Testing

Verify color contrast ratios meet WCAG AA standards (4.5:1 for normal text, 3:1 for large text).

  • Body text has sufficient contrast ratio (4.5:1)
  • Heading text has sufficient contrast ratio
  • Link text has sufficient contrast ratio
  • Button text has sufficient contrast ratio
  • Focus indicators have sufficient contrast
  • Information is not conveyed by color alone
  • Site works with high contrast mode

4. Mobile Accessibility Testing

Test touch accessibility on mobile devices and screen orientations.

  • Touch targets are at least 44px × 44px
  • Content reflows properly in portrait/landscape
  • Text is readable without horizontal scrolling
  • Mobile menu is accessible via touch and screen reader
  • Zoom to 200% works without horizontal scrolling
  • All functionality available in both orientations

5. ARIA and Semantic HTML Testing

Verify proper semantic structure and ARIA implementation.

  • Proper heading hierarchy (no skipped levels)
  • Semantic HTML elements used appropriately
  • ARIA labels provide additional context where needed
  • ARIA live regions announce dynamic changes
  • Form controls have proper labels or descriptions
  • Button roles and states are correct
  • Navigation menu has proper ARIA attributes

6. Performance Impact on Accessibility

Ensure performance optimizations don't hurt accessibility.

  • Lazy-loaded content is announced to screen readers
  • Animations respect prefers-reduced-motion
  • Focus management works with dynamic content
  • Loading states are accessible
  • Error states are properly announced

7. Automated Testing Tools

Run automated accessibility tests using various tools.

Browser Extension Tests

  • axe DevTools: Install Extension
  • WAVE: Install Extension
  • Lighthouse: Built into Chrome DevTools

Command Line Tools

# Install axe-core CLI
npm install -g @axe-core/cli

# Run accessibility audit
axe ../index.html --exit

# Install Lighthouse CLI
npm install -g lighthouse

# Run Lighthouse accessibility audit
lighthouse ../index.html --only-categories=accessibility --view
